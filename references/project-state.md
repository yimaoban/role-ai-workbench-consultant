# 项目进度记录

为每个工作台项目维护一份可继续使用的 Markdown 状态文件，建议命名 `YYYY-MM-DD_项目名_V版本号_进度.md`，写在该项目可写目录。启动或接续时先读取；每次访谈、确认或实现后更新。文档内容是可追溯的项目记忆，不能代替用户的明确确认。

```markdown
# 项目进度

- 项目名：
- 服务岗位/使用对象：
- 当前阶段：访谈 / 数据分析 / 需求待确认 / 视觉待确认 / 开发 / 验收 / 完成
- 当前版本与更新时间：
- 需求确认：未确认 / 已确认（用户原话或明确指令、时间、文档版本）
- 视觉确认：未确认 / 已确认（用户原话或明确指令、时间、方案版本）
- 开发验收：未验收 / 附条件通过 / 已通过（依据、时间、版本）

## 已确认事实
| ID | 内容 | 来源 | 确认时间 |
|---|---|---|---|

## 业务模块与任务
| 模块 ID | 模块 | 任务/触发/步骤 | 输入 | 规则与人工判断 | 输出与合格标准 | 频率/痛点 |
|---|---|---|---|---|---|---|

## 模块关系与数据流
<!-- 记录先后、共享、重复录入、跨模块汇总，必要时链接关系图。 -->

| 数据 ID | 对应模块 | 字段/格式/时间范围 | 来源位置 | 获取方式/授权 | 更新频率 | 状态 |
|---|---|---|---|---|---|---|

## 方案追溯
| 任务 ID | 需求/功能 ID | 页面或实现 ID | 测试 ID | 状态 |

| 问题 ID | 当前假设或缺口 | 影响 | 需谁确认 | 状态 |

## 决定与变更

## 下一步

```

如果任务转移到另一个会话或工作区，将这份记录和对应的已确认交付物提供给后续智能体。没有记录时，只能依据当前可见材料重建，不能假装知道之前的访谈结论。
