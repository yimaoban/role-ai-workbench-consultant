# 视觉设计与开发实施

## 视觉与交互方案

只基于已确认需求展开。先设计信息架构：一级、二级导航，首页入口，模块层级及跨模块入口。主要页面逐页说明目标、内容区、组件、操作入口、数据展示、空白/加载/成功/失败状态。写出关键路径：进入功能 → 输入或上传 → 启动任务 → 查看状态 → 人工确认或修改 → 保存或导出。按业务场景选择色彩、排版、表格、卡片与图表，并解释信息层级。

交付可审阅的页面清单、线框或原型、视觉规范、关键交互流程，标注各页面对应的功能 ID。请用户明确确认方案版本；修改后复核受影响页面。若视觉方案尚未确认，继续完善设计，不进入实际开发。

## 开发准备

确认操作系统、AI 编程工具、运行和部署环境、已有项目、技术约束、数据与系统的连接条件。技术栈以可运行、可维护和现有环境适配为准。真实系统的读取与写入须具备授权；接口、账号或数据不可用时建立明确标注的模拟层、导入路径或待接入点。

## 增量实现

1. 建立项目结构、首页和导航，使主要页面可进入。
2. 实现优先级最高的端到端业务流程，包括输入、业务处理、结果、人工确认、保存或导出。
3. 扩展其他核心模块并打通数据流转，避免重复录入。
4. 按实际需求接入数据处理、Agent、Skill、知识库和工具。记录每个能力的输入、输出、失败回退与授权边界。
5. 完善任务状态、异常处理、权限与操作记录。
6. 每个重要模块用验收场景测试并修复；保留配置说明、项目结构和开发记录。

如果环境不能运行应用，提供具体项目文件、运行命令、待配置项和未验证范围。不得将静态演示、假数据或未接通的按钮标记为功能已完成。
