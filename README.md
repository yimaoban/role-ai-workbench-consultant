# 岗位 AI 工作台搭建顾问（role-ai-workbench-consultant）

面向**不熟悉产品设计与编程的业务人员**的 AI Skill：从真实岗位工作出发，通过渐进访谈梳理业务、数据与资源，分阶段确认需求与设计，最后指导或实施可运行的 AI 工作台。

这个 Skill 同时扮演三个角色：**业务分析师**、**产品设计顾问**、**开发助手**。核心原则是「先理解业务，再设计应用；先确认需求，再开始开发」。

## 工作流程

六个阶段按依赖推进，其中需求确认与视觉确认是两道硬门槛。

| 阶段 | 主要产出 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1 岗位访谈与业务拆解 | 业务梳理记录、模块关系与流程 | 关键业务流程足够明确 |
| 2 数据与资源分析 | 数据资源清单、数据流转与可用状态 | 数据来源和访问条件已核查 |
| 3 需求文档 | 岗位工作台需求说明书 | **用户明确确认需求文档** |
| 4 视觉与交互 | 页面结构与视觉设计方案 | **用户明确确认视觉方案** |
| 5 Vibe Coding 开发 | 可运行应用、项目文件与开发记录 | 核心流程经测试 |
| 6 业务验收与迭代 | 测试记录、问题清单、验收结果 | **用户明确验收开发成果** |

用户评论、沉默或「继续看看」不自动等于确认。不把「页面能打开」当作功能完成。

## 使用方式

将本目录安装到支持 `SKILL.md` 规范的 Agent 环境：

- **Codex CLI**：放到 `~/.codex/skills/role-ai-workbench-consultant/`
- **WorkBuddy**：放到 `~/.workbuddy/skills/role-ai-workbench-consultant/`

安装后用自然语言说明岗位与目标即可，例如「我想做一个设备巡检的 AI 工作台」。Skill 会从岗位、日常任务和交付物开始少量提问，而不是一上来就甩完整问卷；每轮会复述已确认事实、标明推断与待确认事项。

## 设计原则

- **渐进访谈**：每轮只围绕一个主题问少量问题，用户随时可纠正模块、优先级与术语
- **可追溯**：每个核心功能都能回溯到岗位任务、数据、规则和验收案例
- **硬门槛**：需求文档与视觉方案必须明确确认后才进入下一阶段
- **诚实标注**：未核实的数据接口或权限写「待核实」，不假设可连接
- **可验收**：用真实或经授权的代表性业务任务验证，不用静态页面冒充工作台
